# NEXSKILL - 意思決定ログ

## フォーマット
各決定は以下の形式で記録する。

```
### YYYY-MM-DD: 決定タイトル
- **決定内容**: 何を決めたか
- **理由**: なぜその判断をしたか
- **却下した案**: 他にどんな選択肢があったか
- **見直す条件**: どうなったら再検討するか
```

---

### 2026-05-30: シングルHTMLファイル構成を採用
- **決定内容**: index.html 1ファイルにCSS・HTML・JSを全て含める
- **理由**: ビルドステップ不要でGitHub Pagesに直接デプロイ可能。技術的なハードルを最小化
- **却下した案**: React/Next.js（ビルド必要）、複数ファイル分割（管理が複雑化）
- **見直す条件**: ファイルが5000行を超えて管理が困難になった場合

### 2026-05-30: Firebase（Auth + Firestore）を採用
- **決定内容**: バックエンドとしてFirebase BaaSを使用。メール/パスワード認証 + Firestoreデータ永続化
- **理由**: サーバーサイドコード不要で静的ホスティングと相性が良い。無料枠で十分な規模
- **却下した案**: Supabase（検討したが Firebase の方が情報が多い）、自前サーバー（管理コスト大）
- **見直す条件**: Firebase無料枠の上限に達した場合、またはFirestoreの制約が問題になった場合

### 2026-06-01: 許可制アクセス方式を採用
- **決定内容**: 管理者が approved_emails コレクションにメアドを登録し、登録済みメアドのみ新規アカウント作成可能
- **理由**: クローズドな学習環境を実現したい。不特定多数に公開する予定がない
- **却下した案**: 招待コード方式、オープン登録 + 後から承認
- **見直す条件**: ユーザー数が増えて個別メアド登録が手間になった場合

### 2026-06-05: コース構造を導入
- **決定内容**: チャプターをコース単位でグループ化。COURSES配列でchapterIdsを管理
- **理由**: AI以外のコンテンツ（Mac操作、ビジネススキル等）も追加する方針に変更したため、分野別整理が必要
- **却下した案**: フラットなチャプター一覧のまま（スケールしない）、タグ方式（UIが複雑化）
- **見直す条件**: コース数が10を超えてカテゴリ分けが必要になった場合

### 2026-06-05: アプリ名を「AI学習ラボ」から「NEXSKILL」に変更
- **決定内容**: アプリ名・サブタイトル・ターゲットをリブランディング
- **理由**: AI限定からビジネススキル全般に方向性を拡大。20代全般をターゲットに変更
- **却下した案**: SkillBox、LearnHub、スキルラボ、Upgrade
- **見直す条件**: ブランド名の商標問題が発生した場合

### 2026-06-05: ユーザー向けAIチャプター生成機能を削除
- **決定内容**: 「探す」タブとAI生成UIを削除。コンテンツ追加はClaude Code経由のみに一本化
- **理由**: コンテンツ品質を管理者が担保したい。APIキー管理の手間をユーザーに負わせたくない
- **却下した案**: 管理者承認制で残す（UIが複雑化）
- **見直す条件**: ユーザーからカスタムコンテンツの要望が強くなった場合

### 2026-06-05: 画面遷移をSCREEN_RENDERERSレジストリ方式に変更
- **決定内容**: switchScreen関数をif-elseの直書きから、オブジェクト登録方式にリファクタ
- **理由**: タブ/画面追加時の修正漏れを防止。存在しない画面IDのタイポもコンソールエラーで検知
- **却下した案**: そのままif-else（拡張性に不安）
- **見直す条件**: 特になし（上位互換の変更）

### 2026-06-05: メアド許可チェックをwhereクエリから全件取得方式に変更
- **決定内容**: approved_emails の照合を `.where('email', '==', email)` から `.get()` + クライアント側フィルタに変更
- **理由**: whereクエリが空結果を返す問題が発生し、全件取得で安定動作を確認
- **却下した案**: Firestoreインデックスの追加確認（原因特定が困難）
- **見直す条件**: approved_emails が1000件を超えてパフォーマンスに影響する場合
